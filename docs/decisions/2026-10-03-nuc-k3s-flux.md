# kinoite-nuc: headless k3s, apps out of the image, updates that apply themselves

## Decision

The NUC12WSKi7 (i7-1260P, 64 GB, 512 GB NVMe, Iris Xe, I225-V) gets a third
image, `kinoite-nuc`, built from this tree in the same CI matrix and signed
with the same key.

- **Base:** `quay.io/fedora/fedora-bootc:44`, with no desktop.
- **Orchestration:** k3s, pinned and baked into the image. Workloads are not in
  the image. They go in a separate GitOps repo that Flux reconciles.
- **Updates:** `bootc upgrade --apply` every Sunday at 04:00. This reboots into
  the new image. The other two images only stage updates.
- **Storage:** NFS from Unraid for media and the SSD pool. App state stays on
  the local NVMe through k3s's local-path provisioner.

## Why

The box's job is hosting apps that change far more often than the OS: Plex,
the *arr apps, Unmanic and game servers. Keeping them out of the image means an
app change is a commit to the GitOps repo that Flux applies in minutes, not an
image build plus a reboot.

k3s brings Helm charts and operators: the Intel GPU device plugin for QuickSync
and the Tailscale operator for putting services on the tailnet. Neither has a
Quadlet equivalent.

A headless server has no one to reboot it, so stage-only updates would never
land. A weekly window makes the outage predictable.

## Alternatives rejected

- **Podman Quadlets baked into the image, the north pattern.** This is simpler
  on a single node and consistent with the rest of the repo. Rejected because
  every app change would need an image rebuild and a reboot, and there is no
  Helm or operator ecosystem.
- **k3s with the manifests in this repo.** This keeps one repo, but app churn
  would trigger image CI on every push and mix into the image's history.
- **The `fedora-kinoite:44` base, like the other two.** It would reuse the full
  shared baseline, but it ships a whole Plasma session plus Chrome and
  1Password to a server that will never run a desktop.
- **Stage-only updates, like the other two.** On a box that never reboots,
  staged updates never apply.
- **App state on NFS.** The SQLite databases in Plex and the *arr apps corrupt
  over NFS locking. NFS carries media only.
