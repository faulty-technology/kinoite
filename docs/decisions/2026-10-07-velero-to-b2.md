# Velero to B2 for nuc backups

## Decision

- **Where app state lives.** App state (configs, SQLite databases) lives on
  local-path volumes on the NUC's NVMe. Unraid NFS serves media (`arrdata`) and
  non-database shared data (`appdata`).
- **What backs it up.** Velero, deployed by Flux, backs up every namespace
  except `kube-system` and `velero` to a private B2 bucket. Volumes go through
  kopia file-system backup. Schedules: daily at 02:30 kept 14 days, and Sunday
  03:00 kept 90 days (America/New_York).
- **Consistency.** Each app's own scheduled database backup, set to daily, is
  captured with its config directory. There are no backup hooks and no
  downtime.
- **Secrets.** The B2 key and the kopia repository password are SOPS Secrets
  in homelab and are also kept in 1Password.

## Why

This is the shape AKS uses: an in-cluster agent writing to object storage
outside the cluster. B2 is offsite and S3-compatible, and it doubles as the
long-term copy.

Keeping SQLite on local disk is required, not a preference. SQLite needs file
locking that network filesystems don't provide reliably, and Servarr and Plex
both warn that databases on network shares get corrupted.

## Alternatives rejected

- **App databases on the NFS share, synced to long-term storage.** SQLite
  corrupts over NFS.
- **External database for the apps.** Plex is SQLite-only. Postgres would
  cover only Sonarr, Radarr and Prowlarr, and would add a service without
  removing the need for local disk and backup.
- **k8up.** It's a restic operator, Kubernetes-native and lighter. Velero was
  chosen as the tool closest to AKS practice.
- **VolSync.** It needs the volume-snapshot CRDs even in Direct mode.
- **Host restic timer in the image.** It's the simplest, but restores would be
  a runbook rather than Kubernetes resources.
- **Unraid as the target** (NFS folder, or MinIO/Garage for S3). It's local,
  so not offsite, and needs a server added to Unraid.
- **Velero pre-backup hooks** (`sqlite3 .backup`). These need per-app hook
  commands and `sqlite3` in each image. App-native backups give the same
  guarantee with no extra work.

## Cost

- **Velero runs privileged.** The node-agent and the data-path pods
  (`privilegedFsBackup`) must be, on SELinux-enforcing k3s
  ([runs/2026-10-07-nuc-velero-restore-drill.md](../runs/2026-10-07-nuc-velero-restore-drill.md)).
- **The repository password can't be changed in place.** It was set before
  the first backup; changing it means starting new repositories.
- **Only mounted volumes are backed up.** File-system backup skips a volume
  whose app is scaled to zero.
- **A B2 outage or lost key stops backups.** The BSL then goes Unavailable,
  which `bootstrap.sh` checks.
